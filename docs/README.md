# Digital Tennis 개발 시작 안내

이 프로젝트는 외장 IMU가 부착된 NU40-DK 라켓 컨트롤러, Windows BLE 연결, Unity 게임, 별도 AI 모듈, 온라인 매칭 서버를 12일 동안 3명이 함께 개발합니다. 실제 제품 구현에 들어가기 전에 무엇을 만들고 어떻게 완료를 판단할지 합의하는 문서입니다.

## 처음 참여하는 개발자의 읽는 순서

1. [프로젝트 목표와 완료 범위](project/overview.md)를 읽습니다.
2. [초보 개발자 작업 방법](guides/contributing.md)에서 브랜치·커밋·PR을 연습합니다.
3. [저장소 책임](project/repositories.md)에서 내 제품과 다른 제품의 경계를 확인합니다.
4. [제품별 과제](products/README.md)에서 배정받은 문제의 입력·출력·예외·검증 조건을 읽습니다.
5. [WBS](planning/wbs.md)에서 선행 작업과 제출할 결과를 확인합니다.

## 반드시 유지하는 조건

- 하드웨어는 **NU40-DK + 별도 부착형 외장 IMU**입니다. 보드 내장 센서를 전제하지 않습니다.
- IMU 모델·전압·통신 버스·배선 핀은 실제 부품 데이터시트와 보드 리비전 확인 후 D1에 기록합니다.
- 모든 저장소는 `digital-tennis-*` 이름의 공개 저장소입니다.
- 1인 플레이는 하·중·상 AI를 제공하고, 2인 플레이는 방 코드와 서버 시그널링을 통해 P2P 연결을 시도합니다.
- 직접 P2P와 서버 릴레이는 별도 검증 항목입니다. 릴레이 성공만으로 P2P 구현을 완료 처리하지 않습니다.
- 개발은 12일·3명 범위입니다. D1은 실제 착수일이며 특정 달력 날짜를 가정하지 않습니다.

## 이 문서의 규격과 상태

통신 필드, 임계값, 타임아웃, 코트 크기는 개발을 시작할 수 있도록 정한 **초기 설계값**입니다. D1 계약 검토 후 채택하며, 변경할 때 관련 테스트 벡터와 소비 제품을 함께 수정합니다. 아직 구현·실기 검증된 값으로 해석하지 않습니다.

제품 구현 여부는 코드·테스트 로그·시연 자료로 판단합니다. 상세 기준은 [통합 검증](testing/acceptance.md)에 있습니다.
