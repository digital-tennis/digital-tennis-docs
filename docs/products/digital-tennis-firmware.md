# 외장 IMU 펌웨어 개발 과제

저장소: [digital-tennis-firmware](https://github.com/digital-tennis/digital-tennis-firmware)  
초기 담당 역할: A

NU40-DK에 별도로 부착한 IMU의 데이터 획득, 보정, 스윙 인식, BLE 전송를 구현합니다. 아래 과제는 최초 문제 명세이며 현재의 구현 완료표가 아닙니다. 소프트웨어 구조·코덱·SDK는 [검토 중인 구현 PR](https://github.com/digital-tennis/digital-tennis-firmware/pull/1)과 [현재 확장 작업](../project/software-completion.md)에서 확인합니다. 실제 외장 IMU/라디오 검증은 유예 상태입니다. 각 입력·출력과 예제를 먼저 재현하고 예외 조건을 추가하세요. [WBS](../planning/wbs.md)의 과제 번호로 작업을 연결합니다. 초기 숫자 설정은 실제 환경 검증 후 변경 이력과 함께 조정할 수 있습니다.

## 공통 준비

- D1 [환경·물품 확인](../project/overview.md)에서 실제 도구와 버전을 기록합니다.
- [컨트롤러 계약](../contracts/controller-protocol.md)과 [온라인 계약](../contracts/online-protocol.md) 중 관련 경계를 읽습니다.
- [작업·PR 방법](../guides/contributing.md)에 따라 작은 결과와 증거를 제출합니다.
- 정상 예제와 실패 예제를 확인한 뒤 다른 제품에 연결합니다.

## FW-01

### 구현할 동작

**외장 IMU를 연결하고 배선을 설명하기**

NU40-DK는 통신과 계산을 담당하고 IMU는 별도 모듈로 부착합니다. 실제 센서의 모델과 보드 리비전은 아직 정해지지 않았습니다. 추정 핀 번호로 배선하지 않고 부품 데이터시트를 근거로 연결 계획을 작성해야 합니다.

### 선행 조건과 입력

선행 조건: 없음

보드 실물·리비전, 외장 IMU 모델·데이터시트, 사용할 I²C 또는 SPI, 전원 공급 방법.

### 출력과 반환값

hardware.md: 부품 모델, 논리 전압, VCC/GND/데이터 핀, 풀업·주소 선택 핀, 센서 ID 레지스터, 라켓 장착 방향.

### 동작 규칙

- 데이터시트의 전원 전압과 I/O 허용 전압을 구분합니다.
- 실제 사용 가능한 확장 핀과 디버깅·다른 기능의 충돌을 확인합니다.
- I²C이면 주소와 풀업 유무, SPI이면 CS·모드·클럭 상한을 기록합니다.
- 전원을 켜기 전에 A가 배선표와 실물을 대조합니다.

### 입력과 기대 결과 예제

```text
입력: 실제 IMU 모듈의 I²C 사양
출력: VCC/GND/SDA/SCL의 보드 핀과 근거가 있는 배선표
미확정 모델: UNCONFIRMED 표시 후 센서 초기화 작업을 시작하지 않음
```

### 예외와 경계 조건

센서 모델 불명, 5V 전원과 3.3V 논리 혼동, 풀업 중복·누락, 뒤집힌 커넥터, 기존 핀 점유를 각각 확인합니다.

### 권장 구현 순서

1. 데이터시트에서 전원·통신·ID 부분을 찾습니다.
2. 보드 핀맵과 실제 헤더를 대조합니다.
3. 장착 그림과 배선 사진을 남깁니다.

### 완료 판정

- 다른 개발자가 문서만 보고 같은 부품·배선을 식별할 수 있습니다.
- 모든 전압·핀·주소에 근거 또는 미확정 상태가 있습니다.

### 제출할 결과

부품표, 배선표, 장착 사진, 사용한 데이터시트 링크.

## FW-02

### 구현할 동작

**외장 IMU 드라이버로 6 축 샘플 읽기**

게임 동작을 판단하기 전에 센서 통신이 정상인지 확인해야 합니다. 드라이버는 테니스 점수나 스윙 종류를 계산하지 않고 정확한 단위의 센서 샘플만 반환합니다.

### 선행 조건과 입력

선행 조건: FW-01

확정한 센서 설정과 버스, 읽은 raw ax/ay/az/gx/gy/gz, 단조 deviceTimeMs.

### 출력과 반환값

ImuSample {deviceTimeMs, accelG[3], gyroDps[3], sensorReady}; 초기화·읽기 실패는 구별 가능한 오류 코드.

### 동작 규칙

- ID를 읽고 해당 모델의 기대값과 비교한 뒤 초기화합니다.
- 초기 샘플링 목표는 100Hz이며 실제 데이터율과 측정 주기를 기록합니다.
- raw 값의 부호와 데이터시트 감도를 사용해 g·deg/s로 변환합니다.
- 연속 읽기 실패 3회면 sensorReady=false로 전환하고 재초기화합니다. 실패를 0 값 정상 샘플로 반환하지 않습니다.

### 입력과 기대 결과 예제

```text
테스트용 감도: 16384 LSB/g, raw accel=[0,0,16384]
기대: accelG=[0,0,1]
주의: 16384는 예제값이며 실제 감도는 선택 센서의 범위 설정에서 얻음
```

### 예외와 경계 조건

잘못된 ID, 버스 타임아웃, 샘플 누락, 음수 raw, 포화 값, 시간 wrap을 검사합니다. 포화 샘플은 별도 표시하고 스윙 신뢰도를 떨어뜨립니다.

### 권장 구현 순서

1. ID 읽기 한 번을 성공시킵니다.
2. 단위 변환을 가짜 레지스터로 검증합니다.
3. 100Hz 반복 읽기와 실패 주입을 구현합니다.

### 완료 판정

- 정지·여섯 방향·회전에서 부호와 단위가 설명과 맞습니다.
- 10초 샘플 수와 누락 수를 보고합니다.
- 센서 분리 시 오류 상태가 나타나고 게임 입력을 생성하지 않습니다.

### 제출할 결과

드라이버, 설정값·감도표, 실물 ID와 6 축 로그, 가짜 버스 오류 테스트.

## FW-03

### 구현할 동작

**라켓 좌표계와 정지 영점 보정**

센서가 라켓에 돌아간 방향으로 장착될 수 있고 자이로에는 정지 오차가 있습니다. 같은 스윙이 같은 축과 부호로 인식되도록 변환과 보정을 먼저 만들어야 합니다.

### 선행 조건과 입력

선행 조건: FW-02, PR-01

센서 샘플 200개(100Hz에서 약 2초), 센서→라켓 축 변환, 왼손 여부.

### 출력과 반환값

CalibrationResult {success, gyroBiasDps[3], referencePose, reason}; 이후 샘플은 라켓 축 단위.

### 동작 규칙

- 초기 정지 판정은 모든 샘플에서 |gyro|<5deg/s, 가속도 크기 0.9~1.1g입니다.
- 정지 여부를 통과한 200개 샘플로 자이로 평균 bias를 구합니다.
- 움직임이 검출되면 보정을 실패시키고 기존 성공 보정값은 유지합니다.
- 가속도 전체에서 중력을 빼서 정지 값을 0으로 만들지 않습니다. 자세용 중력 성분과 스윙용 성분을 구분합니다.
- 왼손 반전과 센서 장착 변환은 명시한 순서로 한 번만 적용합니다.

### 입력과 기대 결과 예제

```text
정지 gyro=[1,-2,0.5]가 200회 → bias=[1,-2,0.5]
다음 측정 [11,-2,0.5] → 보정 gyro=[10,0,0]
중간 한 샘플 |gyro|=20 → MOVED, calibrated 상태 변경 없음
```

### 예외와 경계 조건

샘플 부족, 센서 미준비, 움직이는 중 보정, 센서 포화, 좌우 장착, 재보정 실패를 검사합니다. 임계값은 실기 기록을 근거로 수정할 수 있습니다.

### 권장 구현 순서

1. 축 변환을 [1,0,0] 같은 벡터로 검증합니다.
2. 평균 bias 계산을 독립 함수로 작성합니다.
3. 정지 판정과 성공·실패 ACK를 연결합니다.

### 완료 판정

- 좌우 장착에서도 기준 전방·오른쪽·위 방향이 같습니다.
- 보정 중 움직이면 CALIBRATION_FAILED가 나옵니다.
- 성공 후 정지 오차를 측정하여 전후 값을 기록합니다.

### 제출할 결과

축 변환 그림, 보정 함수, 정지/움직임 예제, 실측 전후 로그.

## FW-04

### 구현할 동작

**필터와 스윙 이벤트 인식기**

동작 인식은 드라이버와 분리합니다. 6 축 값으로 라켓 위치를 계속 적분하기보다 회전 속도·자세·스윙 구간을 사용해 타격 이벤트를 생성합니다. 녹화 입력만으로 반복 검증할 수 있어야 합니다.

### 선행 조건과 입력

선행 조건: FW-03

시간순 보정 ImuSample 스트림, handedness와 축 규칙, 필터·임계값 설정.

### 출력과 반환값

스윙마다 하나의 SwingEvent {eventId, kind, power, yawDeg, pitchDeg, calibrated}; 원인과 인식 상태 디버그 로그.

### 동작 규칙

- 초기 저역 필터: filtered=0.25*new+0.75*previous. 첫 값은 그대로 사용합니다.
- IDLE→ACTIVE는 |gyro|≥120deg/s, ACTIVE→종료는 |gyro|<60deg/s가 50ms 지속할 때입니다.
- ACTIVE 중 peak가 180deg/s 미만이거나 구간이 40ms 미만·600ms 초과이면 이벤트를 버립니다. 종료 후 200ms는 COOLDOWN입니다.
- 초기 분류: peak 시점 라켓 pitch≥45 도이고 gyroX<-120이면 서브, 나머지는 gyroY 부호가 양수이면 포핸드·음수이면 백핸드입니다. gyroY=0이면 unknown으로 버립니다.
- power=round(clamp((peak-180)/(700-180),0,1)*100). 임계값·부호는 실제 장착 데이터로 검증·기록한 후 조정합니다.

### 입력과 기대 결과 예제

```text
필터 이후 gyro 크기: 0→150→440→40(50ms)
peak gyroY>0, pitch=10 도 → forehand, power=50, 이벤트 1개
종료 직후 흔들림 150 → cooldown 때문에 추가 이벤트 없음
```

### 예외와 경계 조건

정지 잡음, 보정 미완료, 센서 오류, 누락 간격>100ms, 너무 긴 동작, 센서 포화는 이벤트를 생성하지 않거나 해당 구간을 취소합니다.

### 권장 구현 순서

1. 필터를 독립 함수로 구현합니다.
2. 상태기계를 숫자 배열로 검증합니다.
3. 분류·파워를 분리하고 실제 동작에 정답 라벨을 붙여 비교합니다.

### 완료 판정

- 같은 녹화 데이터는 같은 이벤트를 반환합니다.
- AT-03의 정지 오검출과 AT-04의 세 유형 정확도 기준을 충족합니다.
- 재전송과 관계없이 실제 스윙 ID는 하나입니다.

### 제출할 결과

인식기, 임계값 설정, 정답이 있는 녹화 데이터, 오검출·분류 표.

## FW-05

### 구현할 동작

**BLE GATT와 보정 명령 전송**

Windows PC가 표준 Service를 찾고 스윙을 구독해야 합니다. 센서 루프가 BLE 송신을 기다리며 멈추지 않도록 이벤트 큐를 사용합니다.

### 선행 조건과 입력

선행 조건: PR-02, FW-03, FW-04

SwingEvent·버튼·상태 이벤트, 연결/CCCD 상태, RX의 20 바이트 CALIBRATE 명령.

### 출력과 반환값

계약 UUID의 광고·GATT, 정확한 20 바이트 Notify, 명령 ID가 같은 ACK.

### 동작 규칙

- contract의 TX Notify/RX Write with response를 구현합니다.
- 구독 전·끊김 후에는 이벤트를 보내지 않으며 오래된 스윙을 연결 후 재생하지 않습니다.
- SWING은 같은 eventId·원래 시각으로 3회 보내고 sequence는 매번 증가시킵니다.
- 상태는 연결 직후와 초당 1회 보고합니다. 이벤트 큐는 초기 32개이며 가득 차면 가장 오래된 이벤트를 버리고 dropCount를 디버그로 남깁니다.
- 잘못된 명령은 실행하지 않습니다. 보정 완료 ACK, BUSY, SENSOR_NOT_READY, CALIBRATION_FAILED를 구별합니다.

### 입력과 기대 결과 예제

```text
연결·Notify 구독→스윙 ID7
출력 sequence=42/43/44, eventId=7, deviceTimeMs는 모두 동일
CALIBRATE commandId=9→센서 움직임→ACK kind=3 eventId=9
```

### 예외와 경계 조건

CCCD 미설정, 센서 미준비, 가득 찬 큐, 중복 명령, write 실패, 전송 도중 단절을 검증합니다.

### 권장 구현 순서

1. 고정 STATUS 패킷 알림부터 성공시킵니다.
2. protocol C 코덱으로 이벤트를 인코딩합니다.
3. 큐·명령 처리와 실제 인식기를 연결합니다.

### 완료 판정

- Windows에서 UUID와 20 바이트 패킷을 볼 수 있습니다.
- 센서 읽기는 BLE 전송 실패에도 계속됩니다.
- 한 보정 명령에 성공/실패 결과를 확정하고 잘못된 CRC는 실행하지 않습니다.

### 제출할 결과

GATT 정의, 알림 로그, CCCD·명령·단절 테스트, Windows 도구 화면.

## FW-06

### 구현할 동작

**버튼과 오류 상태 및 실물 장착 검증**

컨트롤러는 손에 들고 쓰므로 버튼 튐·흔들리는 배선·센서 분리·연결 끊김을 정상 경로와 함께 다뤄야 합니다. 시작·확인·일시정지 버튼 수와 핀은 실제 보드에서 확인합니다.

### 선행 조건과 입력

선행 조건: FW-05

확정한 버튼 GPIO, 센서 준비/보정 상태, BLE 연결 상태, 실제 라켓 장착.

### 출력과 반환값

BUTTON이벤트, 상태 표시·로그, 실기 실행 및 설치 안내.

### 동작 규칙

- GPIO가 30ms 같은 상태를 유지한 뒤 눌림을 확정하며 누르고 있는 동안 반복 이벤트를 만들지 않습니다.
- sensorReady=false 또는 calibrated=false이면 SWING을 중단하고 STATUS로 알립니다.
- 연결이 끊겨도 센서 상태를 유지하되 미전송 스윙 큐를 비웁니다.
- 재연결·재부팅에 필요한 사용자 행동과 보정 절차를 문서에 씁니다.

### 입력과 기대 결과 예제

```text
0/1로 5ms 간격 튐 뒤 1을 30ms 유지 → BUTTON 1회
누른 상태 1초 유지 → 추가 이벤트 0
센서 제거 → sensorReady=false, SWING 0
```

### 예외와 경계 조건

버튼이 없는 리비전은 실제 핀·외부 버튼 또는 가상 버튼 대체를 D1 결정 기록에 남깁니다. 없는 배터리 측정을 임의로 100%로 표시하지 않고 255를 보냅니다.

### 권장 구현 순서

1. 버튼 녹화 배열로 debounce를 검증합니다.
2. 센서·BLE 오류를 강제로 만들고 상태를 확인합니다.
3. 실제 장착 후 30분 관측과 재연결을 수행합니다.

### 완료 판정

- AT-01~07의 하드웨어 관련 결과가 기록됩니다.
- 버튼 10회에 중복 입력이 없습니다.
- 배선·빌드·업로드·보정 안내를 다른 사람이 재현합니다.

### 제출할 결과

버튼 매핑, 실물 사진, 오류/연속 실행 로그, 펌웨어 설치 문서.
