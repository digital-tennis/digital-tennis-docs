## AI-01

### 구현할 동작

**Unity에 의존하지 않는 AI 상태와 결정 API**

AI 저장소는 게임 씬이 없어도 평가할 수 있는 C# 라이브러리입니다. 상태를 받아 이동·타격 의사결정을 반환하며 공이나 점수 자체를 변경하지 않습니다.

### 선행 조건과 입력

선행 조건: GM-01/02의 좌표 계약

AiState {tick, dt, playerId, playerPos, opponentPos, ballPos, ballVel, phase, bounceCount, incomingBallId}, Difficulty, seed.

### 출력과 반환값

AiDecision {moveTarget, shouldSwing, kind, power01, aimX, aimZ}. no-action은 shouldSwing=false입니다.

### 동작 규칙

- UnityEngine·GameObject·Transform을 참조하지 않습니다.
- 상태는 읽기 전용이며 호출 후 입력 객체 값을 바꾸지 않습니다.
- PAUSED·POINT_END·MATCH_END에서는 타격하지 않습니다.
- AI는 공 상태나 점수를 직접 수정하지 않고 동작 결정만 반환합니다.

### 입력과 기대 결과 예제

```text
phase=PAUSED→shouldSwing=false
같은 AiState·seed로새 policy2개실행→동일 decision
입력 ballPos는호출전후동일
```

### 예외와 경계 조건

NaN·무한수, 잘못된 dt, 없는 플레이어, 초기 상태, 멈춘 공을 검사합니다.

### 권장 구현 순서

1. C# 독립 프로젝트와 API를 만듭니다.
2. no-action 정책으로 단독 실행합니다.
3. game adapter가 결정을 RacketInput으로 변환하게 합니다.

### 완료 판정

- Unity 없이 단독 테스트를 실행합니다.
- game이 AI 정책 구현을 복사하지 않고 의존성으로 사용합니다.

### 제출할 결과

독립 라이브러리, 상태·결정 API, 단독 예제.

## AI-02

### 구현할 동작

**공 착지점과 이동 목표 예측**

공이 어느 쪽으로 오는지와 첫 착지점의 대략적 위치를 계산합니다. 완전한 미래 시뮬레이션이 아니라 현재 중력 모델의 예측으로 시작합니다.

### 선행 조건과 입력

선행 조건: AI-01

ball position/velocity, gravity=9.81, 바운스 면 높이(공 반지름), 코트 경계.

### 출력과 반환값

Prediction {valid, timeToBounce, landingPosition}과 자신의 코트 내부 moveTarget.

### 동작 규칙

- y(t)=y0+vy*t-0.5*g*t²가 바운스 면과 만나는 양의 근을 사용합니다.
- x·z는 현재 속도로 예측합니다. 스핀·네트·바운스 이후 복잡한 예측은 후속 범위입니다.
- 예측 시각 상한은 3초이며 유효하지 않으면 기본 위치로 복귀합니다.
- 상대편으로 가는 공은 무조건 추격하지 않고 자신의 코트에서 대기합니다.

### 입력과 기대 결과 예제

```text
y0=1m,바운스면 0,vy=0,vx=2,vz=4→t≈0.4515초
landing x≈0.903,z≈1.806(원점기준)
이미바닥아래·정지공→invalid,기본목표
```

### 예외와 경계 조건

음의 판별식, 중력 0, 미래 근 없음, 코트 밖, 공이 자신에게 오지 않는 상태, 직전 바운스 상태를 확인합니다.

### 권장 구현 순서

1. 순수 착지 함수에 숫자 예제를 넣습니다.
2. 코트 clamp와 기본 목표를 추가합니다.
3. game 물리와 예측 차이를 측정합니다.

### 완료 판정

- 예제 오차가 시간 1ms, 위치 1cm이내입니다.
- 불가능한 상태에서 NaN 목표를 반환하지 않습니다.
- easy 정책이 자동 이동과 기본 스윙을 낼 수 있습니다.

### 제출할 결과

착지 함수·목표 선택, 숫자 검증·game 비교 로그.

## AI-03

### 구현할 동작

**하·중·상 난이도 정책**

난이도 차이는 반응 시간·목표 오차·의도적 실수로 만듭니다. 어려움은 정확한 정책이지만 항상 승리하는 AI를 뜻하지 않습니다.

### 선행 조건과 입력

선행 조건: AI-02

AiState, 난이도 설정, seed 기반 난수, 예상 타격 시각과 incomingBallId.

### 출력과 반환값

난이도별 이동·샷 결정과 같은 공에 한 번인 스윙.

### 동작 규칙

- 초기 하: 반응 350ms, 위치 오차 ±1.5m, 타격 시도 확률 0.65. 중: 200ms, ±0.8m, 0.85. 상: 100ms, ±0.25m, 0.95입니다.
- 이 설정은 측정 전 초기값이며 승률 보장이 아닙니다.
- 반응 지연은 tick·dt 누적으로 계산하고 Thread.Sleep으로 게임을 멈추지 않습니다.
- 난수는 외부 seed로 고정하고 전역 Random을 사용하지 않습니다.
- 같은 incomingBallId에 이동 오차·실수 난수를 한 번 뽑고 프레임마다 바꾸지 않습니다.
- 이동 오차는 각 수평 축에 uniform[-error,+error]로 더하고 코트 안으로 제한합니다. 타격 시도는 uniform[0,1) 값이 설정 확률 미만일 때만 허용합니다.
- 반응 시간이 지난 뒤 공과 거리 1.5m이내, 높이 0.2~2.5m, 유효한 RALLY 상태에서 shouldSwing을 한 번 반환합니다. 게임은 같은 조건을 다시 확인합니다.
- 초기 샷 파워는 하 0.50·중 0.65·상 0.80, aimZ=0입니다. 상대의 x 위치가 0이상이면 aimX=-0.5, 음수이면 +0.5로 빈 쪽을 겨냥합니다. 상대 위치를 AiState에 명시적으로 추가하고 플레이어 방향 변환은 game이 수행합니다.

### 입력과 기대 결과 예제

```text
동일도달상태,시작후 150ms
hard→반응가능;medium/easy→대기
실수난수 u=0.80→easy 시도안함,medium/hard 시도
새공 ID→새결정샘플
```

### 예외와 경계 조건

지원하지 않는 난이도, 경기 중 난이도 변경, 같은 공의 반복 Update, 너무 짧은 타격 구간을 검사합니다.

### 권장 구현 순서

1. 설정을 데이터로 분리합니다.
2. 반응 타이머·실수·오차를 각각 검증합니다.
3. 세 난이도를 game adapter에서 선택합니다.

### 완료 판정

- 세 설정이 예제 반응 시간·실수 확률대로 동작합니다.
- 같은 공에서 shouldSwing은 최대 1회입니다.
- 온라인 모드에서는 AI가 동작하지 않습니다.

### 제출할 결과

난이도 설정·정책, seed 별 출력, 실수·타격 사례.

## AI-04

### 구현할 동작

**반복 실행과 난이도 검증 도구**

AI를 포트폴리오로 평가하려면 같은 조건을 다시 실행할 수 있어야 합니다. 함수 테스트와 게임 플레이 관측을 구분합니다.

### 선행 조건과 입력

선행 조건: AI-03

정해진 상태 스트림·seed 목록·난이도, 일시정지와 새 공 ID 사례.

### 출력과 반환값

결정 로그·반응 시간·실수·중복 타격 통계, 실제 AI 경기 기록.

### 동작 규칙

- 동일 입력·seed를 2회 실행해 완전히 같은 결정 로그를 비교합니다.
- 고정 seed 여러 개로 설정값의 차이를 관측하되 소수 게임 승률을 보편적인 결론으로 쓰지 않습니다.
- Unity 없는 테스트와 Unity 플레이 결과를 별도로 기록합니다.
- 입력 상태를 직접 바꾸거나 불가능한 타격을 낸 사례는 실패로 남깁니다.

### 입력과 기대 결과 예제

```text
seed42·state-streamA·medium→run1=run2
1000개의새공이벤트→중복스윙 0
반응시간검증:easy>=350ms,medium>=200ms,hard>=100ms
```

### 예외와 경계 조건

seed 재설정, 프레임 시간 변동, PAUSED 동안 타이머 진행, 공 ID 변화, 무효 벡터를 검사합니다.

### 권장 구현 순서

1. 순수 수치·API 테스트를 모읍니다.
2. seed와 로그를 재생 가능하게 저장합니다.
3. 세 난이도로 실제 1게임씩 플레이합니다.

### 완료 판정

- AT-10·11 결과와 재현 입력이 있습니다.
- 난이도 차이와 남은 문제를 설명할 수 있습니다.

### 제출할 결과

단독 테스트 도구, 정책 로그·게임 영상·README.
