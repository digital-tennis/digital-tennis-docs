# 통합 수용 테스트와 증거

> 초기 설계/과제와 현재 완료 상태는 다릅니다. [2026-10-16 구현 현황](../project/implementation-status.md)을 먼저 확인하세요. 직접 P2P·실물 BLE·Windows 실기는 별도 증거가 필요합니다.

각 결과에는 제품 버전·커밋, 환경, 입력, 기대 결과, 실제 결과, Pass/Fail/Blocked, 증거 경로를 기록합니다. 아래는 구현 후 수행할 검증 계획이며 현재 성공 기록이 아닙니다.

| ID | 준비·동작 | 기대 결과 | 증거 |
| --- | --- | --- | --- |
| AT-01 | 외장 IMU 실제 배선 후 ID 읽기 | 해당 부품 데이터시트의 ID와 일치 | 모델·핀맵·사진·로그 |
| AT-02 | 정지 10초, 여섯 방향 자세, 회전 | 가속도·각속도 단위와 축 부호가 문서와 일치 | 원시/변환 샘플 |
| AT-03 | 정지 상태 보정 후 30초 유지 | 보정 성공 상태, 스윙 오검출 1회 이하 | 센서 녹화·인식 로그 |
| AT-04 | 포핸드·백핸드·서브 각 10회 | 각 유형 8회 이상 맞게 검출, 중복 게임 입력 0회 | 동작별 정답·결과 표 |
| AT-05 | 프로토콜 정상·오류 벡터 C/C# 해석 | 값·오류 코드 일치, sequence wrap 처리 | 테스트 출력 |

| AT-07 | 보드 전원 끄고 재연결 | 연결 상태 표시, 과거 입력 재생 없음 | sessionId 변화·로그 |
| AT-08 | 가상 입력으로 서브·2폴트·렛·랠리·아웃 | 1회 득점, 올바른 서버/사이드와 상태 | 규칙별 화면·상태 |
| AT-09 | 점수 3:3→4:3→4:4→5:4→6:4 | 듀스→어드밴티지→듀스→어드밴티지→승리 | 순수 점수 테스트 |
| AT-10 | 동일 AI 상태·seed를 반복 실행 | 동일 의사결정, 난이도별 파라미터 차이 | 정책/seed/출력 |
| AT-11 | 실제 컨트롤러로 AI 세 난이도 1게임씩 | 타격·득점·승패 가능, 입력 누락 기록 | 플레이 영상·이슈 |
| AT-12 | 두 Windows PC에서 코드 생성·참가 | 같은 방 2명, 3번째·잘못된 코드 거절 | 서버·클라이언트 로그 |
| AT-13 | 시그널링 후 직접 DataChannel 송수신 | 직접 P2P 경로와 같은 경기 점수 | 후보 종류·카운터·영상 |
| AT-14 | P2P를 강제로 실패시킴 | 8초 후 relay 합의, 양쪽 mode·epoch 일치 | 전환·relay 카운터 |
| AT-15 | 지연 100ms·중복 입력·오래된 snapshot 주입 | 중복 타격/득점 없음, tick 역행 없음 | 모의 전송 로그 |
| AT-16 | 게스트 연결 종료 후 유예 내 재접속 | 일시정지·스냅샷 재동기화·재개 | 상태·epoch·기록 |
| AT-17 | 호스트가 유예 이후에도 복귀하지 않음 | 무효 종료, 대기 방·자원 정리 | 양쪽 종료 화면 |
| AT-18 | 깨끗한 PC 환경에서 릴리스 실행 안내 수행 | Windows 빌드·펌웨어·서버 재현 가능 | 체크리스트·버전 |
| AT-19 | GitBook 가져오기·GitHub 문서 변경 | 목차·이미지·과제 읽기 및 변경 반영 | 실제 사이트 링크 |

입력 지연 목표는 같은 PC의 BLE 수신→게임 소비 구간 p95 100ms 이하로 설정합니다. 물리적 동작→화면 지연은 별도 촬영·동기화 실험 없이 이 값으로 주장하지 않습니다. 온라인 지연 테스트는 재현 도구·환경과 실제 관측값을 함께 보고하며 모든 인터넷 환경에 대한 보장을 하지 않습니다.

AT-13 실패를 AT-14 성공으로 덮어쓰지 않습니다. 하드웨어가 한 개이면 실제·가상 구성과 두 컨트롤러 검증 상태를 따로 기록합니다.
