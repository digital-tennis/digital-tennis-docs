# 위험과 일정 조정 기준

12일 36인일에는 기술 검증, 멘토링, QA와 문서화를 포함합니다. D11~D12를 새 기능 확대에 사용하지 않습니다.

| 위험 | 조기 판정 | 대응 | 완료 보고 |
| --- | --- | --- | --- |
| 외장 IMU 모델·배선 미확정 | D1 부품표, D2 ID 읽기 | A 우선 투입, 다른 팀은 가상 입력으로 계속 | 실제 센서 성공 또는 하드웨어 미완료 |
| Windows BLE와 Unity 백엔드 충돌 | D2 Windows standalone 수신 | A/C 검토, 검증된 어댑터 후보로 좁힘 | 네이티브 연결과 가상 연결 구분 |
| P2P 패키지 지원 문제 | D3 두 Windows 빌드 문자열 교환 | 후보 버전 고정·짧은 대체 검증, 게임은 릴레이로 진행 | 직접 P2P 실패는 미충족으로 명시 |
| NAT 직접 연결 실패 | D8 다른 네트워크, ICE 경로 기록 | 8초 내 릴레이 협의, 선택적으로 TURN 후속 검토 | TURN/WS 중계를 직접 P2P로 표기하지 않음 |
| 스윙 오인식 | D5 정지·스윙 녹화 입력 | 좌표계·보정·임계값 우선 조정 | 측정 데이터와 정확도 포함 |
| 초급자 과부하 | 매일 PR 단위 결과 | 작은 과제로 분할, A 검토, 그래픽 효과 축소 | 기능별 미완료 목록 |
| 실제 장비 1세트 | D1 수량 확인 | 두 번째 PC 가상 입력, 실물 2세트는 별도 | 장비 구성을 기록 |
| 기능 추가로 일정 초과 | D8 필수 경로 점검 | 복식·랭킹·정밀 추적·복잡한 스핀 제외 | 필수 경로와 남은 작업 공개 |

프로토콜·득점 규칙 변경은 세 제품 이상에 영향을 줄 수 있습니다. 변경 이유, 소비 제품, 새로운 예제, 적용 커밋을 함께 기록합니다. 요구 범위를 줄이는 결정이 필요하면 팀이 명시적으로 합의하고 이전 요구가 완료된 것처럼 처리하지 않습니다.
