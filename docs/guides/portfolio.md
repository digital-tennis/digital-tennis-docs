# 포트폴리오 제출과 릴리스

각 저장소는 다른 사람이 단독으로 역할과 구현을 이해할 수 있어야 합니다. 저장소가 공개라는 사실만으로 구현 완료를 의미하지 않습니다.

## 제품별 증거

| 제품 | 남길 자료 |
| --- | --- |
| firmware | 외장 IMU 모델·배선·좌표계·보정, 실기 데이터, 빌드·업로드, 센서 오류 처리 |
| protocol | 바이트 배치, 정상/오류 벡터, C/C# 왕복 검증, 변경 이력 |
| ble-unity | Windows 환경, 검색·Notify·재연결, 가상 입력, 메인 스레드 처리 |
| game | 씬 구조, 점수 상태기계, AI/온라인 연결, Windows 실행 파일, 플레이 영상 |
| ai | Unity 독립 API, 착지 예측, 난이도 정책, 동일 seed 재현 결과 |
| match-server | 방 생명주기, 두 클라이언트 시연, P2P 시그널링·릴레이의 구분, 실행 설정 |
| docs | 과제·WBS·수용 테스트 결과, GitBook 링크, 결정 기록 |

## README에 들어갈 내용

목적, 현재 구현 상태, 설치 환경과 버전, 실제 실행 명령, 입력·출력 예제, 테스트 방법, 설계 선택 이유, 남은 문제, 관련 저장소 링크를 씁니다. 초기 스캐폴드에서 제시된 예상 폴더를 실제 구현 구조로 갱신합니다.

## D12 릴리스

제품 간 함께 검증한 SHA를 하나의 버전표로 기록합니다. 실행 파일은 정상적인 릴리스 자산으로 올리고 Unity Library/Temp 또는 빌드 캐시는 소스에 넣지 않습니다. 데모는 외장 센서 타격, AI 세 난이도, 두 PC 코드 참가, 직접 P2P, 강제 릴레이 순으로 구성합니다. 실제 코드의 사용 조건과 제3자 자산 라이선스를 확인한 뒤 팀의 라이선스를 선택합니다.
