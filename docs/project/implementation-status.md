기준: 2026-10-16. **12일·3명·외장 IMU 별도 부착**은 최초 제품 계획입니다. 아래는 실제 소프트웨어 구현 현황이며 계획표를 소급해서 완료 처리하지 않습니다.

## 게임 완성도 개선

선수는15본의 개별 스킨 메시·가중치 관절 변형과4표정을 사용합니다.15인 각각의 얼굴/체형/헤어/의상은 JSON, 실제 인정된 공 접촉과 발 접지는 표시용IK로 연결합니다. 스킬은 개인별5키포즈/카메라/효과로 구성하고 종료 시 원래 경기 시점으로 복귀합니다. 전문 모션 캡처나 상용 원작 모델을 구매/복제한 결과가 아닙니다. [품질 작업 현황](game-quality.md)에서 범위와 남은 확인을 추적합니다.

15개 경기장은 공통 코트 판정을 유지하고 표면 재질·개별 기하 문양·원본 도시/자연 배경·시간대 조명·하늘과 외곽 건축으로 구분합니다. 대진 소개에서 전경을 보여준 뒤 경기 카메라로 복귀하고 움직임 줄이기는 이 전환도 생략합니다. 624석과 관중 502명, 점수판·벤치·광고판·조명, 관중의 GPU 움직임을 포함합니다. 낮음/보통/높음 그래픽 설정은 렌더링만 바꿉니다.

음악 A/B10곡과 효과음/환경음11개는 직접 합성했습니다. 캐릭터 기본/대체120개·심판10개 영어 음성은Flite로 합성한 초안이며 한국어 자막이 있습니다. 총151cue이고 듀스/중요 포인트 음악을 점수로 전환합니다. 기존85cue 외부 CSV의 사용자 행/음량은 보존하면서 새 선택 음원을 보충합니다. 영국·미국 등 특정 국적의 발음을 재현했다고 주장하지 않습니다. 청음 후 파일을 바꾸고 `audio.csv`를 다시 읽을 수 있습니다. 사람의 음향 승인과 전문 배우 녹음은 구현 검증과 별개입니다.

## 규칙과 데이터의 기준

게임의 `Assets/StreamingAssets/Balance/` 아래 `gameplay.csv`, `characters.csv`, `rules.csv`, `gestures.csv`, Effects 아래 `effects.csv`, Audio 아래 `audio.csv`를 기준으로 합니다. 규칙은 경기 시작에 고정합니다. 사용자의 외부 CSV를 기본 파일로 덮어쓰지 않습니다. 잘못된 재로드는 기존 유효 설정을 유지합니다.

공격/수비로 스킬 게이지를 획득하고 최대 3개를 저장합니다. 가득 찬 3개 뒤에는 숨겨진 4번째 사용권이 쌓이지 않습니다. 현재 K 버튼과 일반 Skill 입력이 동작합니다. 국가별 제스처 토큰 템플릿은 게임 측 경계까지 구현되어 있으며 실제 IMU가 토큰을 정확히 분류하는지는 아직 실물 검증하지 않았습니다.

## 온라인 계약의 실제 구현

현재 실행 경로는 **WebSocket 릴레이**입니다. offer/answer/ICE 중계 기능과 직접 P2P의 실제 게임 전송을 혼동하지 않습니다. 호스트만 공/규칙/점수를 계산하고 게스트는 순번·epoch가 검증된 버퍼를 표시합니다. Near/Far는 고정 선수 ID이며 엔드 교대 시 공유 좌표를 뒤집지 않습니다. 각 카메라가 자기 선수를 아래에 보여줍니다.

종료된 같은 matchId에 대해 양쪽이 재경기를 요청해야 새 matchId로 시작합니다. 한쪽 요청, 취소, 끊김은 즉시 새 경기를 시작하지 않습니다. 이전 matchId의 늦은 입력과 오래된 snapshot은 반영하지 않습니다. 헛스윙도 고유 swingId·타격 종류·나이·접촉/서브 여부로 전달하며 재접속 상태를 새 애니메이션으로 재생하지 않습니다.

## 증거 읽는 방법

게임 저장소의 `docs/polish-validation.md`에 테스트 수, 빌드, 실제 두 게임 프로세스 결과와 제한을 기록합니다. `tools/verify-online.mjs`는 일반 입력 adapter와 메뉴를 통해 경기하며 점수를 직접 수정하지 않습니다. 캐릭터 갤러리는 스킬 사용권을 부여한 **연출 미리보기**이고 실제 충전 증거와 구분합니다.

Mac이 잠긴 상태에서는 OS 화면·다른 앱을 캡처하지 않고 게임 카메라만 PNG로 저장합니다. 음향 검증 WAV는 게임의 AudioListener 혼합 결과이며 마이크/시스템 음성 녹음이 아닙니다. 같은 Mac 두 프로세스의 성공을 서로 다른 두 PC/WAN/실물 IMU의 완료로 바꾸지 않습니다.

## 다음 개발자의 재현 순서

1. game의 Unity 6000.3.26f1과 고정 AI 패키지 SHA를 확인합니다.
2. `bash tools/unity.sh check`, `test-edit`, `test-play`, `build-mac` 또는 `build-windows`를 순서대로 실행합니다. 같은 프로젝트의 Editor를 먼저 닫습니다.
3. 서버에서 `npm ci`, `npm test`, `npm start`를 실행합니다. 다른 PC는 localhost 대신 접근 가능한 WSS 주소가 필요합니다.
4. game의 `tools/verify-online.mjs`와 `docs/polish-validation.md`로 자동 검증을 재현합니다.
5. 실물 작업은 firmware→protocol→ble-unity 과제 순서로 진행합니다. 게임 입력은 IPlayerInputSource→PlayerInputRouter→PlayerInputAdapter→SubmitInput 경계를 유지합니다.

## 확인된 실행 수치

Unity EditMode150개·전체PlayMode35개, 전경 추가 뒤 메뉴4개, 서버24개 검사가 통과했습니다. Mac GPU batch에서15인·15코트 양 시점/전경과151cue 오디오 로드/교체, 실제 랠리/득점/다음 서브를 확인했습니다.6종 실제 타격·7서브·28접촉과20회 추가 랠리에서 최대 접촉/접지/디딘 발 프레임 이동은0.002mm 미만이었습니다.

온라인 두 프로세스는87포인트·2–0세트(7–6,6–0)와 연결 복구epoch2, 양쪽 동의 재경기의 첫 포인트[1,0]을 일치시켰습니다. 서브/스윙/접촉 앵커·효과 버퍼와 반대 시점·이동을 확인했습니다. 이것은 같은Mac의 두 게임이며 서로 다른 두PC/Windows 실기와 구분합니다.

전체225매치업/3난이도/3시드/3입력전략/2선공을 전후각12150사례·48600포인트로 측정해 체력 비용CSV를 조정했습니다. 종료 체력1 미만 비중21.4%→14.7%이며 사람 승률이나 경쟁적 밸런스의 최종 승인은 아닙니다. 능력치 합420은 유지했습니다.
