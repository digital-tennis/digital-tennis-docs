# 프로젝트 목표와 완료 범위

라켓을 휘두르는 동작을 외장 IMU로 감지하고 BLE로 PC에 전달하여, Unity 테니스 게임에서 타격 시점과 방향·강도를 조절합니다. 캐릭터 이동은 게임이 자동 처리합니다. Nintendo 스포츠 게임의 접근성에서 영감을 얻되 자체 코드와 자체 시각 자산을 사용합니다.

## 데모 경기 규칙

현재 게임은 단식 3세트 중 2세트 선승을 기본으로 사용합니다. `rules.csv`로 5세트 중 3세트 선승도 설정할 수 있습니다. 포인트는 0·15·30·40, 듀스 후 2포인트 차이로 게임을 획득합니다. 한 세트는 6게임 이상·2게임 차이로 승리하며 6–6에서는 7점 이상·2점 차이 타이브레이크를 진행합니다. 기본 최종 세트도 같은 타이브레이크 규칙입니다. 게임마다 서버가 교대하고 타이브레이크는 첫 서버 1포인트, 이후 2포인트씩 교대합니다. 홀수 게임 종료 및 타이브레이크 6포인트마다 엔드를 교대합니다. 두 번 연속 서비스 폴트는 상대 득점이며, 유효한 서비스의 네트 터치는 렛으로 재시도합니다. 규칙 CSV를 다시 읽어도 진행 중 경기는 유지하며 다음 새 경기부터 적용합니다.

코트의 x축은 좌우, y축은 위, z축은 길이 방향입니다. 네트는 z=0, 플레이어 0은 z<0, 플레이어 1은 z>0에 있습니다. 단식 경계는 x=±4.115m, z=±11.885m, 서비스 라인은 z=±6.40m입니다. 구현에서는 공 중심의 첫 바운스 좌표로 라인을 판정하고 경계는 포함합니다. 이는 12일 데모를 위한 단순화이며 공 접촉 면적 전체를 계산하지 않습니다.

자신이 마지막으로 친 공이 상대 코트에 유효하게 한 번 바운스한 뒤 두 번째 바운스하면 자신이 득점합니다. 첫 바운스가 상대 코트 밖이면 마지막 타격자가 실점합니다. 유효 서비스 전에는 리시버의 타격을 받지 않습니다. 랠리에서는 발리 또는 첫 바운스 후 타격을 허용하며 동일 공의 같은 타격 구간에 중복 타격은 무시합니다. 규칙 확장은 공통 합의 후 진행합니다.

## 개발 전 필요한 물품과 결정

| 항목 | 확인할 내용 | 완료 시점 |
| --- | --- | --- |
| NU40-DK | 보유 수량, 리비전, 디버거, 빌드·업로드 도구 | D1 |
| 외장 IMU | 정확한 모델, 데이터시트, 전압·I²C/SPI, ID 레지스터 | D1 |
| 배선·장착 | 실제 핀맵, 풀업 유무, 납땜·커넥터, 고정 방향 | D1~D2 |
| Windows PC | 2대, BLE 어댑터, 목표 Windows 버전 | D1 |
| Unity | 팀이 동일하게 설치할 Editor·빌드 백엔드·패키지 버전 | D1 |
| 개발 환경 | 펌웨어 SDK, C 도구, C# 런타임, 서버 런타임 | D1 |
| P2P 후보 | Windows 실행 파일에서 DataChannel 송수신 가능한 후보 | D3 판정 |

실물 컨트롤러가 1세트이면 한쪽은 가상 컨트롤러로 2PC 통신을 검증할 수 있습니다. 이 경우 결과에 `실물 1세트 + 가상 1세트`를 명시하고 두 개 실물 컨트롤러 검증은 미완료로 남깁니다.

## 완료 기준

D12에 외장 IMU→BLE→Unity 타격, 세 난이도의 AI 경기, 2PC 코드 참가와 동일 점수, 직접 P2P와 강제 릴레이를 각각 보여줍니다. 실행 파일·펌웨어·서버 실행 안내와 검증 기록을 각 저장소에 연결합니다. 실제 구현이 없는 항목은 미완료로 표시합니다.
